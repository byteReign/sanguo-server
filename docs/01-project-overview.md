# 三国砍王 - 项目总览

## 项目定位

轻量级三国放置成长游戏，点击泰坦类微信小游戏。

**核心玩法**：挂机 + 点击 + 成长 + 收集 + 排行榜

**开发团队**：1-2人

**技术栈**：
- 前端：Cocos Creator + TypeScript（微信小游戏）
- 后端：Go + Gin + MySQL + Redis

## 已确定的设计决策

### 1. 登录方式
使用设备 ID 直接登录，不走微信授权流程。

**原因**：
- 简化开发，减少审核复杂度
- 1-2人项目，不需要复杂的用户体系
- 设备 ID 足够满足需求

**实现方案**：
- 前端：`wx.getSystemInfoSync().deviceId` 或 `wx.getStorageSync('deviceId')`
- 后端：接收 deviceId，不存在则自动注册，存在则返回用户信息

### 2. 项目规模
个人/2人项目，保持简单。

**原则**：
- V0 上线前，不写世界Boss、不写聊天、不写联盟
- 先跑通核心循环，再考虑扩展
- 能复用的不复造轮子

### 3. 题材
三国背景，前期不复杂。

**第一阶段敌人**：黄巾之乱（黄巾兵 → 渠帅 → 张角）

## 核心数据流

```
玩家点击/挂机
    ↓
计算伤害（DPS + 点击伤害）
    ↓
扣减敌人血量
    ↓
敌人死亡
    ↓
奖励结算（战力/DPS/图鉴/称号）
    ↓
进入下一关
    ↓
数据同步到服务器
```

---

## 接口约定

所有接口统一响应格式：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

- `code = 0` 表示成功
- `code != 0` 表示错误，具体见错误码定义

---

## 注意事项

1. **不要过度设计**：先跑通，再优化
2. **数据一致性**：战斗结果以服务器为准，前端只做展示
3. **防作弊**：关键数值（战力、DPS、关卡进度）服务器校验
4. **离线收益**：记录上次在线时间，上线时计算离线收益
5. **排行榜**：用 Redis ZSET 实现，定时刷新
